# qa_bench

The benchmark is the acceptance test for frame selection. It asks the same questions about the same video of different strategies, grades the answers and compares accuracy against input tokens.

| Strategy | What the model gets |
| --- | --- |
| `baseline` | One full-resolution frame every 2 s (`--baseline-every`), like an agent dumping frames itself |
| `digest_nozoom` | The engine's timeline and contact sheets |
| `digest` | The same, plus a batched `get_frames` zoom tool (up to 3 rounds) |

## Run it

Install once: `uv pip install -e '.[dev,bench]'` (ffmpeg on `PATH`).

```bash
# Synthetic, offline: no model calls, runs in CI (~5 s, video generated on first use)
python -m bench.qa_bench synthetic

# Showreel, offline: token estimates and build time only
export VIDEO_DIGEST_SHOWREEL=/path/to/benchmarket-showreel.mp4
python -m bench.qa_bench showreel

# Showreel, live: real accuracy and tokens, 3 runs × 3 strategies + judge calls (about $1 on Opus 5.5)
python -m bench.qa_bench showreel --live

# Your own video. Without "answer" fields the baseline's answers become the reference
python -m bench.qa_bench my.mp4 --questions my-questions.json --live
```

Live runs use the Anthropic SDK's default credentials (`ANTHROPIC_API_KEY` or an `ant auth login` profile). `--model` defaults to `claude-opus-5-5` and `--judge-model` to `claude-haiku-5-5`. The prototype's reference numbers were measured on `claude-sonnet-5-5`, so pass `--model claude-sonnet-5-5` to compare like with like.

Each run writes `bench/out/<fixture>-<mode>/qa_report.md` and `results.json` (or `--out DIR`). The exit status is 1 when a gate check fails.

### Offline vs live

| | Offline (default) | `--live` |
| --- | --- | --- |
| Accuracy | **Evidence coverage**: a question counts as answerable when a shown frame falls inside its `evidence` span. This is an upper bound, because a frame mid-animation can still be unreadable. Only questions with `evidence` are scored, so the showreel has none. | Answers graded against the answer key (`contains` / `number` / `yesno` checks, plus a judge model for `judge` questions) |
| Tokens | Estimated with `bench/qa_bench/tokens.py` (`--token-profile highres` for current models, `legacy` for ≤1568 px models) | Real usage: input + cache-write + cache-read tokens over every turn, including zooms |
| Consistency, zoom rounds | N/A | Measured over `--runs` (default 3) |

The offline synthetic run is what CI runs. It catches selection changes that drop a whole event (for example a 2-second flash or a scene). It does not catch frames that are kept but unreadable; only a live run catches those.

## Fixtures

- **synthetic**: a 180 s, 1280×720 "slides + screen recording" video generated by `bench/qa_bench/fixtures.py` and cached in `bench/.cache/`. It has static slides, a motion segment, a slow fade, a 2 s flash and a running clock. The answer key and evidence spans are in `fixtures/synthetic/questions.json`. Edit `SCENES` and bump `SYNTHETIC_VERSION` together with the questions.
- **showreel**: the 32 s motion-graphics showreel from the PRD prototype (1920×1080, 22 MB, not in git). Set `VIDEO_DIGEST_SHOWREEL` or drop the file at `bench/fixtures/showreel/benchmarket-showreel.mp4` (gitignored). `fixtures/showreel/questions.json` pins its sha256 (the bench warns on a mismatch) and records the prototype's reference results.

Question format: see the docstring in `bench/qa_bench/grading.py`.

## Quality gate

**No frame-selection change ships unless it holds or improves accuracy at equal or lower tokens.** This covers anything that changes which frames end up in a digest: `select.py`, `sample.py`, `sheets.py`, default `SelectSettings`, and the timeline text.

The gate checks the `digest` strategy (or `digest_nozoom` if `digest` wasn't run) against the PRD targets:

| Check | Target | Showreel reference (prototype v2) |
| --- | --- | --- |
| Accuracy vs baseline | No worse than 10 points below (`--margin`) | 100% vs 71% |
| Input tokens vs baseline | ≤ 25% | 16% (6,688 vs 41,049) |
| Consistency across runs | Same verdict on ≥ 90% of questions, ≥ 3 runs | 15/15 |
| Zoom rounds | Usually 0; at most 3 in any run | 0 |
| Digest build time | Under 1× the video's length | 21 s for 31.5 s |

The change itself is checked with `--against`: keep the `results.json` from `main`, then run your branch with `--against` pointing at it. That adds "accuracy held or improved" and "tokens equal or lower" checks. Live tokens may move up to 2% to absorb jitter (`Targets.token_slack` in `gate.py`).

Checks that a run can't measure show as **N/A** and don't fail the run, so read the table rather than relying on the exit code alone.

### For an engine PR

1. `pytest` passes. It includes the offline synthetic gate.
2. Offline, compare against main:
   ```bash
   python -m bench.qa_bench synthetic --out /tmp/qa-main      # on main
   python -m bench.qa_bench synthetic --against /tmp/qa-main/results.json   # on your branch
   ```
3. For any change to selection logic or defaults, run the showreel live on both and paste both reports' Summary and Quality gate tables into the PR:
   ```bash
   python -m bench.qa_bench showreel --live --out /tmp/qa-main-live           # on main
   python -m bench.qa_bench showreel --live --against /tmp/qa-main-live/results.json
   ```

Try a setting without editing code: `--set threshold=2.0 --set min_gap=1.0`.

## Tests

`tests/test_qa_bench.py` covers grading, the gate, the zoom loop (with a fake client) and the CLI offline on a reduced-resolution synthetic video. None of it calls a model. The one live test is opt-in:

```bash
VIDEO_DIGEST_LIVE=1 pytest tests/test_qa_bench.py -k live          # 1 run, synthetic
VIDEO_DIGEST_LIVE=1 VIDEO_DIGEST_LIVE_RUNS=3 pytest tests/test_qa_bench.py -k live
```
